# Руководство администратора Apollo Native Assist

## 1. Область применения

Native Assist — необязательный серверный компонент Apollo MP Sync. Графический установщик Windows x64 без команд поддерживает только **Docker Compose over SSH**. Администратор не редактирует Compose вручную и не вводит команды shell, Docker или Java. Клиенты не устанавливают Java или Native Assist.

Установка через Coolify недоступна: текущий API не позволяет безопасно и атомарно обновить Compose с условием на ревизию. Изменения Coolify не выполняются; в установщике нет токена, коннектора или скрытого режима Coolify.

Скачайте установщик из [последнего публичного релиза GitHub](https://github.com/ALTIS13/Apollo.PZ-MP-Sync/releases/latest). Клиентский мод доступен как [предмет Steam Workshop](https://steamcommunity.com/sharedfiles/filedetails/?id=3780069702).

## 2. Точно поддерживаемый сервер

Native Assist может активироваться, только если совпадает каждое значение:

| Поле | Требуемое значение |
| --- | --- |
| Приложение выделенного сервера Steam | `380870` |
| BuildID выделенного сервера | `24775771` |
| Версия Project Zomboid | `42.20.3` |
| Версия Java сервера | `25` |
| Операционная система сервера | `linux` |
| Архитектура сервера | `amd64` |
| Дайджест образа контейнера | `sha256:5e3479ea2ef66a4f14686fd3abc3286cf31a82c0e37f737b4b5976ff37da9951` |

Установщик также требует точного совпадения проверенного образа, ENTRYPOINT, пустого CMD, сервиса, контейнера, mounts, networks, ports, restart policy, серверного JAR, нативных библиотек, агента и fingerprint. Неизвестные или изменившиеся данные безопасно блокируют операцию до изменений.

## 3. Поля подключения

Откройте установщик и оставьте режим сервера **Docker Compose over SSH**. Заполните поля графического интерфейса:

- **SSH-хост** и **SSH-порт**;
- **имя пользователя SSH**;
- режим аутентификации: **Закрытый ключ** с файлом ключа и необязательной кодовой фразой либо **Пароль**, только если он выбран явно;
- абсолютный **каталог развёртывания**;
- от одного до восьми уникальных относительных **файлов Compose**, находящихся внутри этого каталога;
- **точное имя сервиса** Project Zomboid.

Учётные данные находятся только в памяти, очищаются на всех конечных путях и не попадают в журнал, резервную копию, recovery metadata или файлы релиза.

## 4. Проверка ключа SSH-хоста

Нажмите **Проверить сервер**. Первое подключение — наблюдение ключа SSH-хоста без учётных данных: пароль, кодовая фраза и закрытый ключ не читаются и не отправляются. Установщик показывает алгоритм ключа и **отпечаток SHA-256** без завершающего символа заполнения.

Сверьте отпечаток по независимому доверенному каналу. Явно подтвердите **Доверять и продолжить** только при совпадении. Отклонение, отсутствие данных, несколько разных ключей, изменение ключа, отмена или тайм-аут останавливают процесс до аутентификации. Аутентифицированное соединение закрепляется за подтверждённым отпечатком и безопасно блокируется при смене ключа.

## 5. Предварительный просмотр и подтверждение перезапуска

После аутентификации установщик выполняет read-only discovery и точную проверку совместимости. Поддерживаемый **предварительный просмотр** перечисляет резервную копию, файлы компонента, изменения environment и override, отключённый перезапуск с проверкой штатного режима, включённый перезапуск с проверкой READY и доступность отката. В просмотре есть только отображаемые цели, без команд, учётных данных, значений environment или полученного Compose.

Проверьте каждое запланированное изменение и перезапуск. Установка остаётся недоступной, пока вы не отметите отдельный флажок **подтверждение перезапуска**, разрешающий перечисленные перезапуски сервиса.

## 6. Установка или обновление

Нажмите **Установить или обновить**. Установщик повторно проверяет сервер, создаёт точную резервную копию до первого изменения, разворачивает Native Assist с выключенным kill switch, проверяет объединённую модель Compose, пересоздаёт выбранный сервис и требует штатный `SERVER STARTED` без маркеров Native Assist.

Затем он включает kill switch, ещё раз пересоздаёт тот же сервис и проверяет одновременно `SERVER STARTED` и точное состояние Native Assist `READY/hooks-armed` при нулевом числе ошибок advice. До сообщения об успешной готовности обязательны оба маркера.

Если после резервной копии возникает отмена или ошибка, установщик выполняет ровно одну попытку отката с независимым от отмены recovery token. При ошибке до резервной копии откат не выполняется, потому что состояние сервера не изменялось.

## 7. Безопасное отключение

Выберите **Безопасно отключить**, чтобы сохранить установленные файлы и recovery record, но выключить закрытый kill switch. Установщик получает новый снимок сервера, меняет только `APOLLO_NATIVE_ASSIST=off`, пересоздаёт выбранный сервис и проверяет штатный `SERVER STARTED` без `READY/hooks-armed` и маркера Java-агента.

После записи значения off отмена уже не прерывает перезапуск и штатную проверку. Если проверка не проходит, установщик сообщает фиксированное состояние ошибки и не включает Native Assist молча.

## 8. Полный откат и восстановление

Выберите **Полностью откатить**, чтобы восстановить точное состояние до установки из резервной копии. Восстанавливаются отсутствовавшие, частичные или полные прежние файлы Apollo и исходная модель Compose, после чего выбранный сервис пересоздаётся ровно один раз и проверяется штатный `SERVER STARTED`.

Локальный recovery record без секретов позволяет предложить восстановление после перезапуска приложения. Необходимы повторная аутентификация и та же проверенная идентичность сервера. Restore выполняет ровно одну попытку отката; неверная запись или путь резервной копии безопасно блокируются без догадок и повторов с другой целью.

Автоматическое восстановление после резервной копии и явный полный откат не показывают путь резервной копии, исходный Compose, команды, учётные данные или текст исключений в видимом журнале.

## 9. Fail-closed поведение и поддержка

Только `READY/hooks-armed` активирует решения Native Assist. Состояния `ABSENT`, `DISABLED`, `INCOMPATIBLE` и `CIRCUIT_OPEN` сохраняют штатную сеть Project Zomboid и поддерживаемое Lua-поведение Apollo. Отсутствующее или несовпадающее окружение, fingerprint, библиотека, hook, маркер готовности или инвариант контейнера никогда не включает частичное нативное поведение.

Native Assist не устраняет задержку, не делает все физические симуляции одинаковыми и не гарантирует совместимость с модом, заменяющим те же действия. Изучите [границы совместимости](COMPATIBILITY.md) и сообщайте о проблемах в [публичном репозитории](https://github.com/ALTIS13/Apollo.PZ-MP-Sync).
